# NAT for IPv6
Because many networks use both IPv4 and IPv6, there needs to be a way to use IPv6 with NAT. This topic discusses how IPv6 can be integrated with NAT. IPv6, with a 128-bit address, provides 340 undecillion addresses. Therefore, address space is not an issue. IPv6 was developed with the intention of making NAT for IPv4 with translation between public and private IPv4 addresses unnecessary. However, IPv6 does include its own IPv6 private address space, unique local addresses (ULAs).

## NAT64
IPv6 is ideally used natively, meaning IPv6 devices communicate through IPv6 networks directly. However, since not all networks have upgraded, transition techniques help IPv4 and IPv6 coexist.
- Dual-Stack: Devices run both IPv4 and IPv6, allowing them to communicate using either protocol.
- Tunneling: Wraps an IPv6 packet inside an IPv4 packet so it can travel through an IPv4-only network.
- NAT for IPv6: Temporarily translates between IPv4 and IPv6 to help with migration, but it is not recommended as a long-term solution.

**NAT-PT vs. NAT64**
- NAT-PT: An older IPv4-to-IPv6 translation method that has been deprecated.
- NAT64: Its replacement, used to facilitate communication between IPv6 and IPv4 networks.
