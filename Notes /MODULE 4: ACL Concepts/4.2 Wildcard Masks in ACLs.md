# Wildcard masks in ACL

## Wildcard Mask Overview
* Long story short, wildcard mask is similar to subnet masks, but instead of each matching bits are true in subnet mask, the reverse is ture for wildcard masks.

Wildcard masks use the following rules to match binary 1s and Os:
* Wildcard mask bit 0 - Match the corresponding bit value in the address
* Wildcard mask bit 1 - Ignore the corresponding bit value in the address

## Wildcard Mask Types

1. Wildcard to match a Host
    * With this, the wildcard mask will permit only SPECIFICALLY the host of the IPv4 address. 
    * For example `access-list 10 permit 192.168.1.1 0.0.0.0`, the IPv4 address of 192.168.1.1 will be the only one permitted specifically.
2. Wildcard to match an IPv4 Subent
    * By implementing a wildcard mask of `0.0.0.255`, it permits all hosts in the 192.168.*1-255* /24 network.
    * This allows every IPv4 address in the subnetwork to be permitted or conditioned through the wildcard mask.
3. Wildcard mask to match an IPv4 address range
    * By implementing an ACE to ACL 10, using the syntax `access-list 10 permit 192.168.16.0 0.0.15.255` it first starts in the third octet for a range, meaning 16 + 15 = 31 (192.168.16.0 - 192.168.31.0) while allowing all 8 bits in the fourth octet. 

## Wildcard Mask Calculation
1. Starting value: `255.255.255.255`
2. Subtract the subnet mask with the starting value, for example: `- 255.255.240.0`
3. Resulting wildcard mask: `0.0.15.255`

## Wildcard Mask Keywords
* Working with decimal representations of binary wildcard mask bits can be tedious. Keywords reduce ACL keystrokes and make it easier to read the ACE.

the two keywords are:
* `host` - This keyword substitutes for the 0.0.0.0 mask. This mask states that all IPv4 address bits must match to filter just one host address.
* `any` - This keyword substitutes for the 255.255.255.255 mask. This mask says to ignore the entire IPv4 address or to accept any addresses.
